# FLOA

מנוע שבונה אתרים סטטיים (HTML, CSS ו-JS), והעסקים והאפליקציות שנבנים ממנו. הכול מוגש על `floa.co.il` ועל התת דומיינים שלו מ-Cloudflare Pages.

האתר נבנה בענן: GitHub Action בונה ומפרסם אותו בכל פוש ל-`main`. בגיט יש רק מקור, ואף קובץ בנוי. הכתובות נגזרות מהחבילה שהבילד מוציא ל-`dist/`, לא ממבנה הריפו.

**לפני שמשנים משהו, קוראים את [`CLAUDE.md`](CLAUDE.md).** שם החוקים של הפרויקט, והוא המקור המעודכן לכל מה שמתואר כאן.

## מה יש בכל תיקייה

- **`apps/`**: תיקייה לכל עסק או אפליקציה (`apps/<key>/`), עם `index.js` (המניפסט) ו-`content/site.js` (הזהות). יש שני סוגים:
  - **מנועי**, כמו `apps/floa/`: מרכיב את הדפים שלו מהרכיבים של `src/`, עם קופי ו-`theme.css` משלו.
  - **ידני**, כמו `apps/chords/` או `apps/roster/`: כל האתר יושב ב-`public/`, והבילד מעתיק אותו כמו שהוא.
- **`apps/floa/domain/`**: הקבצים ששייכים לדומיין ולא לעסק (`/supabase.js`, `/auth.js`, `404.html` ועוד). הבילד מעתיק אותם לשורש.
- **`src/`**: המנוע לאתרי שיווק: רכיבים, מערכת העיצוב, לייאאוטים ועוזרים. אין בו שום דבר של עסק מסוים.
- **`ui/`**: ספריית ה-UI של האפליקציות (CSS, רכיבי JS וסמלים), שנפרסת לשורש הדומיין. החוקים שלה ב-[`ui/SKILL.md`](ui/SKILL.md), וההגדרה של כל רכיב בקובץ משלו ב-[`ui/docs/`](ui/docs/).
- **`worker/`**: ה-Cloudflare Worker שעונה ב-`api.floa.co.il`: לידים מטפסים, ה-API של roster ועוד. פרטים ב-[`worker/README.md`](worker/README.md).
- **`functions/`**: מנתב כל תת דומיין לתיקייה של האפליקציה שלו, לפי `domains.json`.
- **`supabase/`**: ה-Edge Functions של פרויקט ה-Supabase של הדומיין.
- **`scripts/`**: כלים שמריצים ביד, למשל `scripts/sql.mjs`, שמריץ SQL על הדאטהבייס.
- **`.github/workflows/`**: הפריסה ל-Cloudflare Pages וחיבור הדומיינים.
- **`.githooks/`**: ה-pre-commit שחוסם קומיט שיש בו מפתח.
- **`.claude/`**: ההגדרות והסקילים של Claude Code לפרויקט הזה.
- **`dist/`**: תוצר הבילד. גיט מתעלם ממנו.

## קבצים בשורש

- **`build.mjs`**: הבילד. מרנדר כל עסק לתיקייה משלו ב-`dist/`, ומייצר גם `robots.txt`, `sitemap.xml`, `llms.txt` ואת `worker/src/businesses.js`.
- **`domains.json`**: כל הדומיינים והתת דומיינים, ואיזו אפליקציה יושבת מאחורי כל אחד.
- **`package.json`**: הפקודות. לבילד אין תלויות, רק Node.
- **`CLAUDE.md`**: החוקים של הפרויקט. קוראים אותו לפני כל שינוי.

## עסק חדש

פותחים תיקייה חדשה ב-`apps/`. אפשר להתחיל מעותק של `apps/floa/` לעסק מנועי, או של `apps/chords/` לאפליקציה ידנית. הצעדים המלאים, כולל מה צריך להגדיר מחוץ לריפו, כתובים ב-`CLAUDE.md`.

## פקודות

```bash
node build.mjs              # בונה את כל העסקים ל-dist/
node build.mjs --only=floa  # בונה עסק אחד, לפי ה-key שלו
npm run dev                 # בונה, מגיש את dist/ על http://localhost:5173 ובונה מחדש בכל שינוי
npm test                    # הבדיקות שצריכות רק Node
npm run test:layout         # בדיקות התצוגה של Chords ב-Chrome אמיתי, אחרי בילד
npm run hooks               # מפעיל את .githooks, פעם אחת בכל clone
```

## אבטחה

הריפו ציבורי. מפתחות וטוקנים יושבים ב-`.env` בשורש, שגיט מתעלם ממנו, ואף מפתח לא נכנס לקובץ מקומט. ה-pre-commit שב-`.githooks/` חוסם קומיט שמכיל מפתח, ולכן מריצים `npm run hooks` בכל מכונה חדשה.
