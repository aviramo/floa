# chords

אינדקס שירים עם אקורדים, ודף משלו לכל שיר: `chords/<שם_השיר>/`. אפשר להוסיף שיר, לערוך אותו ולמחוק אותו, ואפשר להעלות תמונה או PDF של דף אקורדים והמערכת תקרא ממנו את המילים ואת האקורדים.

הפרויקט עומד בפני עצמו. הוא לא חלק ממנוע FLOA, לא מייבא ממנו כלום, ולא נכנס לבילד שלו.

## איך מריצים

```
node chords/build.mjs      בונה את האתר לתוך chords/dist/
node chords/server.mjs     מגיש אותו על localhost:5175, ומאפשר לכתוב לקבצים
node --test chords/test.mjs
```

הפענוח האוטומטי של תמונות דורש מפתח:

```
ANTHROPIC_API_KEY=sk-ant-... node chords/server.mjs
```

בלי מפתח כל השאר עובד, רק כפתור ההעלאה יגיד שאין לו במה לפענח. אפשר גם להזין מפתח בממשק עצמו, ואז הדפדפן פונה ל-API ישירות והמפתח נשמר במכשיר בלבד. זה נוח לשימוש אישי ולא מתאים לאתר ציבורי.

## איפה נשמרים השירים

**עם `server.mjs` פועל:** כל שיר הוא קובץ ב-`chords/songs/<slug>.json`. שמירה כותבת את הקובץ, בונה מחדש את האתר, והדף `chords/<slug>/` קיים באותו רגע. זאת דרך העבודה הרגילה, וזה מה שנכנס לגיט.

**בלי השרת** (האתר הבנוי מוגש כקבצים סטטיים, או נפתח מהדיסק): אין למי לכתוב, אז הוספה ועריכה נשמרות ב-`localStorage` של הדפדפן. השירים הבנויים ממשיכים להופיע, ושיר שנערך בדפדפן מסתיר את הגרסה הבנויה שלו. לשיר שנוצר ככה עדיין אין דף משלו, אז הוא נפתח ב-`chords/view/?song=<slug>`. כפתור **ייצוא JSON** מוריד אותו, ומספיק לשים את הקובץ ב-`chords/songs/` כדי שיקבל כתובת קבועה.

## הרעיון היחיד שכל השאר נובע ממנו

**אקורד הוא אינדקס של תו במילות השורה, לא מיקום בפיקסלים ולא רווחים.**

```json
{
  "text": "אַךְ טוֹב וָחֶסֶד יִרְדְּפוּנִי כָּל יְמֵי חַיָּי",
  "chords": [{ "i": 0, "c": "C" }, { "i": 18, "c": "G" }]
}
```

זה מה שפותר את הבעיה של מימין לשמאל. דף אקורדים שבנוי מרווחים, כמו בוורד ובגוגל דוקס, נשבר ברגע ששם אקורד באנגלית נופל בתוך שורה בעברית: אלגוריתם ה-bidi מסדר מחדש את הרצף והאקורד מחליק מההברה שלו. אינדקס לא מחליק. הרנדרר חותך את השורה באינדקסים ומרכיב כל פרוסה כ-`inline-block` שנושא את האקורד שלו מעליה, ואז פריסת הטקסט של הדפדפן עצמו היא זו שמצמידה ביניהם, לכל כיוון שהשורה רצה.

בפועל: אין מדידת פיקסלים בשום מקום ברנדור, השורות נשברות לבד כשצריך, וההצמדה מדויקת לפיקסל גם בעברית וגם באנגלית. יש בדיקה שמוודאת בדיוק את זה.

בקובץ ובעורך הטקסטואלי השורה נכתבת inline, בסגנון ChordPro:

```
[C]אַךְ טוֹב וָחֶסֶד [G]יִרְדְּפוּנִי [F]כָּל יְמֵי [G]חַיָּי
```

סוגר מרובע שהוא חלק ממילות השיר נכתב `\[`.

**האקורד יושב תמיד על תחילת אות, אף פעם לא בין אות לניקוד שלה.** "אַךְ" הוא שלושה תווים ואות אחת וחצי, ולכן כל אינדקס עובר `snapToGrapheme` לפני שהוא נשמר או מצויר.

## עריכה

- **לחיצה על מילה** מוסיפה אקורד בדיוק שם ופותחת שדה לשמו.
- **גרירת אקורד** מזיזה אותו. בזמן הגרירה סמן אנכי מראה על איזה תו הוא ינחת, והאקורד עצמו קופץ רק כשמשחררים, כדי שהשורה לא תזוז מתחת לאצבע.
- **חיצים במקלדת** מזיזים אקורד ממוקד אות אחת בכל פעם, **Enter** משנה את שמו ו־**Delete** מוחק אותו.
- **עריכת המילים** בשדה שמתחת לשורה גוררת את האקורדים איתן: הקלדה בסוף השורה לא נוגעת באף אקורד, והקלדה באמצע מזיזה רק את מה שאחריה.
- **עריכה כטקסט** פותחת את כל השיר בפורמט ChordPro, לתיקונים מהירים ולהדבקה מבחוץ.

## פענוח תמונה או PDF

התמונה נשלחת ל-Claude יחד עם סכימה, והמודל מחזיר את השורות בפורמט ה-inline הזה ולא אינדקסים מספריים. זאת החלטה מכוונת: ספירת תווים היא בדיוק מה שמודל שפה עושה כמעט נכון, ו"כמעט נכון" כאן פירושו אקורד שנחת אות אחת מההברה שלו. סוגר שנכתב לפני מילה לא יכול לפספס.

ההנחיה מדגישה במפורש שבשיר בעברית האקורד הימני ביותר הוא הראשון, כדי שהסדר לא יתהפך. אחרי הפענוח התמונה נשארת על המסך לצד העורך כדי להשוות, וכל תיקון הוא גרירה אחת.

## מבנה

```
chords/
  build.mjs         songs/*.json  ->  dist/
  server.mjs        מגיש את dist/ וכותב ל-songs/
  test.mjs          הכללים, בלי דפדפן
  lib/              משותף ל-node ולדפדפן
    chordpro.mjs    פרסור, סריאליזציה, חיתוך לפרוסות, גבולות אותיות
    song.mjs        הצורה האחת של שיר
    render.mjs      הצ'ארט כ-HTML, לדפים הבנויים
    slug.mjs        כותרת -> כתובת
    decode.mjs      הפרומפט והסכימה של הפענוח
  assets/           הצד של הדפדפן
    chart.js        ציור שורה, גרירה, הוספה, כוונון
    editor.js       העורך
    store.js        קבצים דרך ה-API, או localStorage כשאין שרת
    index.js  song.js  app.css
  songs/            שיר לכל קובץ. זה מקור האמת.
  dist/             נבנה, לא בגיט
```

`dist/` נכתב עם נתיבים יחסיים לכל דף, כך שאפשר להגיש אותו משורש הדומיין, מתוך תת-תיקייה, או ישר מהדיסק, בלי לשנות כלום.
